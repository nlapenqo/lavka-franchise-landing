# kit/ — дизайн-система лендингов Яндекс Лавки (супер-шаблон)

Единый язык для всех страниц франшизы: главный лендинг (`site/`) и страница мероприятий (`events/`) разобраны на **основы F1–F8 + 17 блоков LB00–LB16**. Задача — чтобы коллега с задачей «нужен лендинг» собирал страницу из готовых блоков, а не рисовал с нуля. Этап 2 (10.09.2026) — кит переделан по референсу «Web :: Site UI-kit Widgets» (Figma, секция «Скопируй этот шаблон 🙈»): у блоков паспорта свойств, режим «Схема», превью 390, «Примерка» и сборщик страницы. Следующий этап — перенос в Figma (компоненты с теми же пропсами).

## Что внутри
| Файл | Что это |
|---|---|
| `index.html` | Страница кита: обложка «Скопируй этот шаблон» в три шага, основы F1–F8, блоки LB00–LB16 с паспортами, раздел «Примерка и сборщик», «Как собирать». |
| `kit.css` | **Единственный файл стилей для лендингов**: токены, база, компоненты, свечение, анимации, блоки, темы секций, адаптив, reduced-motion. Копируется в проект как есть. |
| `kit.js` | Вся интерактивность лендинга по data-атрибутам (шапка, хиро, барабан, reveal, счётчики, карусель, отзывы, аккордеон, шаги, форматы, свечение карточек, демо-форма, бургер). Скрытые (`hidden`) слайды и шаги пропускает. Копируется как есть. |
| `kit-chrome.css` / `kit-chrome.js` | Оформление и механика самой страницы кита: паспорта, схема, превью, копирование, сборщик, примерка. **В лендинги не копируются.** `kit-chrome.js` подключается до `kit.js` — снимает чистую разметку блоков до того, как kit.js добавит классы и счётчики. |
| `fitting.html` | **«Примерка для маркетинга»** отдельной страницей: медиа-слоты с кодами и размерами, чек-лист блоков с паспортами, «Скопировать HTML страницы». Блоки подтягивает из `index.html` через fetch — открывать через локальный сервер. |
| `template.html` | Стартовая страница: шапка + хиро + цифры + текст-медиа + карточки + FAQ + форма + футер. Альтернатива сборщику. |
| `build-kit.mjs` | Сборка в один файл (шрифты, картинки, оба скрипта внутри): `node kit/build-kit.mjs` → `kit-preview.html`; `node kit/build-kit.mjs template.html template-preview.html`; флаг `--artifact` — без html/head/body для claude.ai-артефакта. |
| `kit-preview.html`, `template-preview.html` | Собранные самодостаточные версии. Не править руками. |
| `TZ-super-template.md` | ТЗ этапа 2. |

Ассеты не дублируются: шрифты из `../site/fonts/`, логотипы и иконки из `../site/assets/figma/`, фото из `../site/assets/figma/business/` и `../events/assets/`.

## Устройство блока (= будущий компонент Figma)
```html
<div class="kit-block" id="b06" data-block="LB06" data-themes="light white dark" data-cards-range="3-6">
  <div class="kit-label">…код, имя, откуда, когда использовать, «Копировать HTML»…</div>
  <!-- паспорт .kit-props рисует kit-chrome.js -->
  <div class="kit-body">
    <section class="section section--light" data-variant="A" data-vname="A — с иконками" data-theme="light" data-html>
      <p class="section-lead" data-slot="lead">…</p>            <!-- необязательная часть: тумблер -->
      <div class="features__grid" data-cards="6">…</div>        <!-- число карточек: лишние скрываются, --n = колонки -->
      <span class="icon-plate" data-kv="IC01_24">…</span>       <!-- медиа-слот: в «Схеме» штриховка с кодом -->
      <h3 data-rule="Заголовок: до двух строк">…</h3>           <!-- правило: в «Схеме» плашка -->
    </section>
    <section … data-variant="B" …>…</section>
  </div>
</div>
```
- **Паспорт** (панель над блоком): Вариант A/B/C, Тема (белая / светлая / тёмная), Карточек (или слайдов, шагов, вопросов), Части (тумблеры `data-slot`), Вид (Дизайн / Схема), Телефон 390. Строка под панелью показывает, как свойства уйдут в разметку: `data-block`, `data-variant`, `data-theme`, `data-cards`, скрытые слоты.
- **Тема** переключает классы `section--dark` / `section--light` (или свои через `data-theme-classes`, как `ticker--navy`) и пишет `data-theme`. Тёмные варианты добавлены в kit.css для хиро-сплита, цифр, текст-медиа, заявления, отзывов, галереи, FAQ.
- **Схема** (`.kit-block.is-scheme`): медиа со `data-kv` — штриховка с кодом слота, `data-rule` — плашки с правилами, `data-slot` — пунктир.
- **Превью 390** — iframe (`srcdoc`) с тем же блоком в том же состоянии; строится лениво, высота по postMessage. Работает и в собранном артефакте.
- **Копировать HTML** — чистая разметка варианта с применённым состоянием: выключенные части и лишние карточки удалены, `hdr--demo` → `data-hdr`, служебные атрибуты сняты.
- **Один блок без хрома**: `index.html?block=LB06&variant=B&theme=dark&cards=4&off=lead&scheme=1`.

## Как собрать лендинг
1. Скопировать `kit.css`, `kit.js` (и ассеты) — или начать с `template.html`.
2. В `index.html` настроить паспорта нужных блоков (вариант, тема, части, карточки).
3. В разделе «Примерка и сборщик» выбрать рецепт (главный лендинг / мероприятие / спецпроект) или отметить блоки вручную → **«Скопировать HTML страницы»** — получится целый документ с `<link>` на kit.css и `<script>` на kit.js, блоки в состоянии из паспортов, порядок как в ките. Отдельный блок — кнопкой «Копировать HTML» у блока.
4. Проверить: `python3 -m http.server 8821` в корне → `http://127.0.0.1:8821/kit/`; кадры `node tools/shot.mjs <url> <out.png> --w 375|1440 --block .section`.
5. Собрать в один файл: `node kit/build-kit.mjs страница.html имя.html`.

## Что не сделано / ограничения
- Мобильный слой — базовый (сетки в колонку, кегли, шапка со знаком и бургером). Пиксельный мобильный макет главного (`site/mobile.css`) не переносился целиком.
- Шаги на десктопе раскрываются по клику; скролл-пин из `site/app.js` в кит не перенесён.
- Форма никуда не отправляет (`data-form` — демо), обработчик — к разработчикам.
- Сборщик не переставляет блоки — порядок фиксирован как в ките (шапка → хиро → … → форма → футер).
- Figma-референс на этапе 2 читался по описанию из ТЗ: официальный Figma MCP в сессии был недоступен. Перенос компонентов в Figma — следующий этап.
